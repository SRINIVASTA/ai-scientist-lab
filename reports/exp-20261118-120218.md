## Abstract
Predicting the direction of a 5‑day price swing from daily OHLCV data is a challenging binary classification problem. A baseline Random Forest model (50 trees, max depth 4) using seven engineered features—including a rolling Shannon entropy—achieved a validation accuracy of **0.4804** and an F1‑score of **0.6459**. This study investigates whether (i) augmenting the feature space with 1‑day and 2‑day lagged versions of each baseline indicator and (ii) expanding the model capacity (200 trees, max depth 8) can improve out‑of‑sample performance. The enhanced pipeline yields a validation accuracy of **0.4888**, representing a **+1.8 %** absolute gain over the baseline without evidence of data leakage.

## Hypothesis
*Title:* Add Lagged Feature Variables and Increase Model Capacity  
*Rationale:* Financial time series display autocorrelation and momentum effects that a single‑snapshot feature set cannot capture. Introducing recent historical values (lags) enables the Random Forest to learn temporal patterns such as trend continuation or reversal. Coupled with a modest increase in tree count and depth, this richer representation is expected to raise out‑of‑sample accuracy for binary swing‑direction tasks.

## Methodology
1. **Data Loading** – `load_market_data()` reads a CSV of OHLCV data (or synthesises a 1500‑row series when absent) and computes the baseline features:  
   - `ret_1d`, `ret_5d`, `ret_20d` (percentage returns)  
   - `vol_10d` (10‑day rolling volatility of 1‑day returns)  
   - `sma_ratio` (price relative to 20‑day SMA)  
   - `hl_spread` (high‑low spread normalized by close)  
   - `shannon_entropy_20d` (rolling Shannon entropy of log returns, window 20, bins 8)  

   The target is the 5‑day forward swing direction (`target`).

2. **Lagged Feature Construction** – For each of the seven baseline columns, two lagged copies are created:  
   ```python
   for col in feature_cols:
       for lag in [1, 2]:
           df[f"{col}_lag{lag}"] = df[col].shift(lag)
   df.dropna(inplace=True)
   ```  
   The final feature set comprises the original seven variables plus 14 lagged variables (21 columns total).

3. **Train‑Validation Split** – A strict chronological split retains the first 80 % of observations for training and the most recent 20 % for validation, preserving temporal causality.

4. **Model Specification** – Two Random Forest configurations are compared:  
   - **Baseline:** `RandomForestClassifier(n_estimators=50, max_depth=4, random_state=42)`  
   - **Enhanced:** `RandomForestClassifier(n_estimators=200, max_depth=8, random_state=42)`

5. **Evaluation Metrics** – Validation performance is measured with **accuracy** and **F1‑score** (binary). Results are saved to `outputs/metrics.json` and visualised via a bar plot.

## Conclusion
Introducing 1‑day and 2‑day lagged versions of each baseline indicator and expanding the Random Forest’s capacity modestly improves out‑of‑sample accuracy for the 5‑day swing direction task (from **0.4804** to **0.4888**). Although the gain is modest, it validates the hypothesis that temporal context and higher model complexity can capture additional predictive signals in financial time series. Future work should (i) compute the corresponding F1‑score for the enhanced model, (ii) explore deeper lag horizons, and (iii) assess alternative tree‑based ensembles or gradient‑boosting methods to further close the performance gap.
